# dsh-hybrid-workspace

一个聊天框，多个互不打扰的工作区。

你继续在同一个窗口里聊天。插件会自动判断这句话属于 A 项目、B 项目还是 C 项目，回答时只带那个项目的范围、记忆和最近几轮，不再把整段历史都塞进来。

## 它能带来什么

- **不再串项目**：A 项目的结论不会被带进 B 项目的回答；切错时，面板里可以改回来。
- **回答更短、更准**：每次只装配相关的工作区、几条相关记忆和最近几轮对话，减少无关历史对注意力的稀释。
- **不用开很多会话**：保留单聊天框的顺手感，不需要每天在多个窗口之间来回切换。
- **结论留得住**：决策、事实、待办和问题会被抽出来；新结论会替代旧结论，但旧结论仍可追溯。
- **一条消息多个话题也能处理**：写成 1、2、3 的分条消息会分别路由，回答也按编号回到对应工作区。
- **看得见、改得动**：面板能看每个区装了什么、为什么这样路由、哪些记忆快过期；可以改名、合并、归档、迁移。
- **换机器也能带走**：支持导出/导入 JSON 和 Markdown，不锁死在一台机器上。

## 适合谁

适合长期在同一个聊天框里并行处理几件事的人：开发、运维、项目交付、日常杂事混在一起，但又不希望每次手动切换会话。

它不追求“全自动理解一切”。默认混合路由只在本地做词面判断；若设置 `llmJudge: true`（混合模式只在模糊裁决时调用）或 `mode: "llm"`，模型裁决会把当前用户消息和最多 5 个候选工作区的 ID/名称发送给当前 DSH 模型服务。设置 `mode: "lexical"` 可强制只用本地路由。拆段和记忆抽取仍是启发式规则，会犯错；面板可用于兜底和纠正。

## 快速开始

在源码目录执行：

```bash
node scripts/install.mjs          # 先看要改什么
node scripts/install.mjs --apply  # 写入 profile
```

装完重启 DeepSeek Harness。之后正常聊天即可，第一条消息会自动建一个工作区。

如果使用 `dshmarket`，也可以直接在插件市场里安装和更新。

## 日常怎么用

1. **直接聊**：按项目、任务或主题自然说话，插件会根据内容把消息放到对应工作区。
2. **一条消息问几件事**：用空行、1/2/3 编号或“另外/还有”分开，插件会拆成最多 3 段分别处理。
3. **需要整理时**：打开面板，把混在一起的内容迁移到新工作区；可以按关键词预览、逐条勾选。
4. **想固定一个话题**：在卡片上把“自动切走”关掉，之后短句和追问都会留在当前区。
5. **换电脑或备份**：面板右上角导出 JSON 或 Markdown；导入时会重新编号，不会覆盖现有工作区。

入口默认是“两跳确认”：没命中已有区时先留在当前区，下一条同主题消息才建新区；明确说“新项目/新工作区”会立即建，同名同路径会复用，活跃区默认最多 12 个。这样寒暄和一次性问题不会把工作区撑爆。

工作区只代表长期项目。超过 7 天的 0 会话空壳、超过 30 天无会话的区、低活跃、同名重复和超过活跃上限的，都只在面板列出建议；插件不会自动归档或合并，所有整理动作都要手动确认。

## 面板

面板地址是当前 DSH 地址加上：

```text
/hybrid-workspace/
```

例如：

```text
http://127.0.0.1:<DSH端口>/hybrid-workspace/
```

重启 DSH 后，会话顶部工具栏会出现一个「工作区」按钮，点它会在当前 DSH 窗口铺开全屏管理面板（窗口内 iframe，地址是 /hybrid-workspace/），浮层右上角有「关闭」，可以随时回到 DSH 首页；旁边还有「浏览器打开」兜底。日常聊天仍然用 DSH 自己的输入框，插件在后台路由工作区并注入上下文，回复也由 DSH 渲染；面板只负责管理，不是聊天页。浮层顶栏是窗口标题栏：按住空白处或「混合工作区」标题即可拖动窗口；macOS 左侧已给红绿灯留出位置，关闭和浏览器打开按钮不会被拖拽区吞掉。这样不受 Electron 把 window.open 交给系统外部浏览器、导致缺少 DSH 登录态的限制。没看到按钮时，先确认插件在设置里已启用，或直接用上面的地址。

里面能看：

- 每个工作区的范围、关键词、记忆和最近对话
- 下一轮会注入多少上下文、由哪些部分构成
- 最近几次路由为什么留下或切走；分错时在同一行改派到别的工作区：这条消息、同一轮回答和本轮记忆会整体搬走，来源区不再保留，目标区记住这次纠正；改派标记重启后仍保留，来源轮次被复用时会拒绝，避免误搬后来的消息
- 全局档案（跨工作区生效的长期偏好）
- 已归档的工作区和可恢复的快照
- 统一收件箱（实验）：把任务写进队列、手动锁定工作区、顺序或并发派发；每个任务在独立的 DSH 子会话里执行，同区串行、跨区最多 2 并发，审批固定为 never，结果只回写任务卡；状态保存失败时页面显示红色横幅，变更接口返回 500，恢复后自动清除
- 收件箱执行只使用已绑定到所选工作区的活跃根会话及其有效工作目录；没有匹配目标时会失败提示。任务运行或取消收尾期间，相关工作区不能被归档、清空、删除、合并或容量淘汰；turn 前取消会立即释放并发锁与工作区锁，超时与取消分别标记。
- 普通聊天会话隔离（实验，试点区）：把工作区策略的「会话隔离」设为「独立子会话」后，主会话只负责路由和展示，实际回答交给该区专用 DSH 子会话；父模型不参与这一轮。子会话只注入本区有限上下文（默认 2400 字符、4 条记忆），父会话只记录用户消息和子会话答案。服务不可用时回退提示词隔离；子会话失败/超时会显示明确错误。子会话只在内存中，插件重启、工作区归档/清空/删除/合并或切回提示词模式即销毁。
- 工作区治理：空壳、长期无会话、低活跃、同名重复和超限只给建议；勾选后可批量归档或按建议合并，插件不会自动执行
- 导出、导入、迁移、合并、改名、归档

### 管理面板（/hybrid-workspace/）

`/hybrid-workspace/` 是唯一入口：统计、收件箱、治理、归档、迁移、导入导出、策略都在这里。日常聊天直接使用 DSH 输入框；工作区路由、上下文注入和会话隔离由插件在 DSH 内完成，回复也由 DSH 渲染。

旧地址 `/hybrid-workspace/shell` 会 302 到管理面板，不再提供聊天式页面。收件箱仍是实验功能，只服务任务派发，不是主聊天。原生 macOS 壳已在 v2.7.0 移除，保留 DSH 窗口内 iframe 和浏览器打开兜底。

## 和哪些插件一起用

| 插件 | 建议 | 说明 |
| --- | --- | --- |
| `dshmarket` | 推荐 | 在 DSH 内安装、更新本插件。 |
| `dsh-cost-meter` | 可选，推荐 | 装了就在面板显示最近 12 个会话的合计费用、token 和调用次数；不装则隐藏。 |
| `billion-context` | 可共存 | 它负责长上下文压缩，本插件负责按工作区装配；同时使用时注意预算叠加。 |
| `dsh-auto-memory` | 可共存，建议分工 | 它是跨 App 的文件型记忆，本插件是工作区内的结构化记忆；建议明确哪套负责长期偏好、哪套负责项目结论。 |
| `dsh-ops` | 可共存 | 终端/运维工具，职责不冲突；插件注入的步骤消息会被过滤。 |
| 其他上下文构成/压缩插件 | 不需要 | 和本插件的预算装配有重叠，容易重复处理同一份上下文。 |

## 常用配置

在 profile 的 `cordis.patch.yml` 对应条目下修改；没写的项用默认值，通常不需要动。

```yaml
- id: hybrid-workspace
  name: dsh-hybrid-workspace-v2
  config:
    mode: hybrid            # hybrid | lexical | llm
    llmJudge: false         # hybrid 默认纯本地；true 才把当前消息和候选交给模型裁决
    ignoreSubagents: true   # 子代理/PTC 子会话不建区、不记记忆
    contextMaxChars: 2400   # 单话题注入上限（字符），约 1.6k tokens；不是所有区相加
    memoryInject: 8         # 最多注入几条相关记忆
    multiTopic: true        # 一条消息拆多个话题
    maxWorkspaces: 60
    activeLimit: 12         # 活跃工作区上限；满了回退当前区/最近区
    newTopicConfirm: 0.12   # 第二跳确认阈值，越低越容易建新区
    inboxExecutor: auto     # auto=DSH 子会话；simulate=只做本地模拟，不调用执行器
    inboxMaxConcurrent: 2   # 跨区并发上限，1-4
    inboxTaskTimeoutMs: 600000  # 单个任务超时，超时主动取消
    inboxContextMaxChars: 2400  # 子会话注入的工作区上下文上限（字符）
    inboxMemoryInject: 4        # 子会话最多注入几条工作区记忆
    isolationPilot: ['ws_59299832', 'ws_f66e8d8b']  # 普通聊天会话隔离试点区；'*' = 全部
    isolationTimeoutMs: 600000  # 隔离子会话等待上限，超时取消并显示错误
    isolationContextMaxChars: 2400  # 隔离子会话只带本区上下文的上限（字符）
    isolationMemoryInject: 4        # 隔离子会话最多注入几条本区记忆
    governanceEmptyTtlMs: 604800000  # 空壳可归档建议阈值（7 天）
    governanceStaleMs: 2592000000    # 无会话长期不活跃阈值（30 天）
    panelPath: /hybrid-workspace
```

每个工作区还可以单独设上下文上限、注入记忆数和是否允许自动切走；留空表示继承全局。会话隔离只对 `isolationPilot` 里的工作区显示和生效，默认仍是 `prompt`。

## 数据与备份

默认状态目录：

```text
$DSH_HOME/hybrid-workspace-v2/
```

- `state.json`：工作区、记忆、全局档案、会话绑定、归档
- `decisions.log`：建区、路由、合并等决策
- `trace.jsonl`：最近的路由判定

状态是本地文件，可备份。需要迁移或长期保存时，优先用面板导出，而不是手改 `state.json`。

## 已知边界

- **默认隔离是提示词级的**：原始会话历史仍在 DSH 自己的日志里；本插件只是不把其他区的内容注入当前回答。试点区把策略切到「独立子会话」后，普通聊天由该区子会话回答，父模型不参与；但子会话只在内存中，重启/归档即销毁，失败会明确报错或回退提示词，不是安全边界。
- **会话隔离审批固定为 never**：隔离/收件箱子会话都不会弹审批；需要审批的操作会被拒绝，不要把它当成提权通道。
- **多话题不隔离**：会话隔离只接管单话题首步；一条消息拆成多个话题时仍由父模型统一回答。
- **规则会犯错**：路由、拆段、记忆抽取都是启发式，不是模型。拆错/并错时，用面板合并、改名或迁移。子代理/PTC 子会话默认不建区（`ignoreSubagents:false` 可关闭），避免 review 提示词被当成用户话题。
- **匹配是词面的**：同义改写、跨语言和极短指代可能漏判；迁移时可以用关键词预览和低分候选补选。
- **单进程状态**：`state.json` 没有跨进程锁，不要多个实例同时写同一个 `$DSH_HOME`。
- **面板只适合本机**：依赖回环地址和 Host 校验，不要暴露到公网或不可信的反向代理。
- **测试只用合成数据**：仓库里的 fixture 不含生产凭据、真实项目或客户数据。

## 开发与测试

```bash
cd dsh-hybrid-workspace-v2
node test/all.mjs            # 全部入口
node test/all.mjs router     # 只跑名字含 router 的入口
```

本地重启 DSH（会关闭当前窗口再重新打开，仅用于 macOS 桌面端开发）：

```bash
./scripts/restart-dsh.py --check              # 只显示当前 DSH 主进程和 host PID
./scripts/restart-dsh.py --detach --delay 15  # 立即返回，15 秒后自动退出并重启
./scripts/restart-dsh.py --dry-run            # 只打印计划，不动 App
./scripts/restart-dsh.py --force              # 30 秒内没退出时强制结束
```

`--detach` 的日志写到 `~/.dsh/restart-dsh.log`，重启结果写到 `~/.dsh/restart-dsh-result.json`，会检查新进程的 `/hybrid-workspace/` 页面版本。旧 App 完全退出后会先等待 3 秒再启动，避开 LaunchServices 和 Electron 单实例锁的残余；如果新主进程启动后很快退出，或没有拉起桌面 host，会自动重试一次。结果里的 `newMainPids`、`newHostPids` 和 `page` 会记录每次尝试的实际情况。这个脚本不参与插件运行时，也不改变工作区数据。

更完整的设计记录和边界说明见 [docs/RESEARCH-v2.md](docs/RESEARCH-v2.md)。
